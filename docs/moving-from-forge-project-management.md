# Moving across from Forge Project Management

Blueworx Forge installs beside the old plugin rather than replacing it. Both run
on the same site, neither touches the other's records, and nothing moves on its
own. So the move is done by hand, at whatever pace suits, and the old plugin
stays there as the record of everything that came before.

## Set the studio up first

In this order, because each step needs the one above it. All of them are under
**Forge** in the WordPress menu.

1. **Clients** — one per client, with their timezone.
2. **Clients → sites** — one per site you look after.
3. **People** — everybody who works on anything, and which client they work for.
4. **Support packages** — the packages you sell, with their hours and term.
5. **Support** — put each site on the package it is actually on, from the date it
   started. This is what creates their hours.
6. **Meetings** — any standing meeting a client has, so the time it takes comes
   out of the right person's week.

Only then is there anywhere sensible to put work.

## Move the work

**Open work only.** Anything already delivered stays in the old plugin. Copying
finished work across buys nothing and costs an afternoon.

For each open item, make it in Forge and fill in what it needs at the stage it
is at: the title, what the problem is, which site it belongs to, and — once it
reaches Up Next — who is doing it, who is reviewing it, who is delivering it,
and how long it will take. Then close the old one so there is only ever one
live copy.

Move a client's work in one sitting rather than a few items at a time. Half a
client in each plugin is the state where somebody works off the wrong list.

## What does not come across

Say so out loud to anyone who will look for it:

- **The history.** Who moved what, and when, starts again from the day the item
  is created in Forge.
- **Hours already used.** A client's balance starts at what their package gives
  them. If they have already spent some of this term's hours, correct the
  balance on the Support screen and say why — the correction shows on the same
  screen the balance does.
- **Discussion and attachments.** They stay in the old plugin.

## Connect the client sites

Each client site runs the client plugin, and each needs its own key: **Clients →
the site → integration key**, then paste it into that site's Forge connection
screen. A key belongs to one site; reusing one is how two clients end up looking
at the same work.

## Turning the old plugin off

When a client has nothing open left in it, they are done. When every client is
done, deactivate Forge Project Management — but leave it installed for a few
months. Deactivating keeps the old records readable if somebody asks what
happened last year; deleting it takes them with it.
