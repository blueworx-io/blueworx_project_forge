# PR 5 — Slack for staff: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each staff member can paste a Slack webhook and be told, in Slack, when work is assigned to them, when something is ready for their review or delivery, when a task they hold a seat on is commented on, and each morning what is due today.

**Architecture:** A `Slack` module with its own small register (`bwx_forge_slack_events`, claim-by-insert exactly as `Notifications\Register` does, kept separate so the client-email outbox never sees a Slack event), a per-person row (`bwx_forge_slack_people`) holding the sealed webhook and preferences, a `Webhook` sender, `Notify` (the five event kinds, each a static method called from the one place the thing happens), and `Morning` (the single WP-Cron job). REST under `/me/slack`; a panel on My tasks; a Slack panel on the Connections admin page; failures listed on Sync health.

**Tech Stack:** PHP, `wp_remote_post`, WP-Cron, React.

**Spec:** `docs/superpowers/specs/2026-09-14-studio-work-recurring-surecart-slack-design.md` (section "PR 5").

## Global Constraints

- Branch `slack-staff`, off `surecart-subscriptions`. Draft PR against it.
- Version `2.105.0`; changelog. Schema `VERSION` +1; two tables.
- Webhook URLs must start with `https://hooks.slack.com/`; sealed with `Tenancy\Secrets`; never returned by any route.
- The cron job sends messages and decides nothing: a missed run is a missed ping.

### Task 1: Tables, `Slack\People`, `Slack\Events`

- `bwx_forge_slack_people`: `user_id` varchar(32) PK, `secret` text, `prefs` text (JSON: assigned, ready, comment, morning — all true by default), `connected_at`, `last_ok_at`, `last_error` varchar(191), `updated_at`.
- `bwx_forge_slack_events`: `id` varchar(48) PK (`slk_` + sha1(kind|subject|user|occurrence)[0:24]), `kind` varchar(20), `subject_id` varchar(32), `user_id` varchar(32), `outcome` ('raised'|'sent'|'retrying'|'failed'|'skipped'), `attempts` int, `last_detail` varchar(191), `payload` text (the message, so a retry sends the same words), `created_at`, `settled_at`. Keys: `user_outcome (user_id, outcome)`.
- `People::connect( user_id, url, prefs )`, `get( user_id )` (no secret), `webhook( user_id ): ?string` (opened), `set_prefs`, `disconnect`, `mark( user_id, ok, error )`, `connected(): array` (every connected person, no secrets), `Events::claim( kind, subject_id, user_id, occurrence, payload ): string|''`, `settle( id, outcome, detail )`, `pending_for( user_id, limit 5 )`, `failed(): array` (for Sync health).
- [ ] PHPUnit: id derivation is stable and distinct per person; prefs default and merge (`People::prefs_from( array $input )` pure). Commit.

### Task 2: `Webhook` and `Notify`

- `Webhook::send( string $url, string $text, array $blocks ): true|WP_Error` — `wp_remote_post`, JSON `{ text, blocks }`, 10 s timeout; 2xx is sent, anything else is the error text.
- `Notify::assigned( array $item, string $seat, string $user_id, bool $new )`, `Notify::ready( array $item, string $stage )` (Reviewer at `in-review`, Deliverer at `completed`; occurrence = cycle), `Notify::comment( array $item, array $comment, string $author_user_id )`, `Notify::morning( array $person, array $items )`. Each: person connected and pref on → `Events::claim` → build blocks (`Message::for( kind, … )`, pure, tested) → `Webhook::send` → `settle`. Before sending, `Notify::retry_pending( user_id )` re-sends up to five `retrying` events (attempts < 3), settling `failed` on the third miss.
- Link in every message: `{app page}#item=<id>` — add to `App.tsx` a hash reader on load that opens the item panel for `#item=…` (WorkScreen `setOpenId` from the hash on mount; small).
- Call sites: `WorkItemsController::create` and `::update` (seat diff → `assigned`), `SubmissionsController` conversion (`assigned`, new=true), `Transition::commit` after a successful move (`ready`), `CommentsController::create` (`comment`).
- [ ] PHPUnit: `Message::for` wording per kind; seat diffing (`Notify::seat_changes( before, after )` pure). Commit.

### Task 3: REST and the My tasks panel

- Routes: `GET /me/slack` → `{ connected, prefs, last_ok_at, last_error }`; `POST /me/slack` `{ url }` → validate prefix, seal, send a test message ("Forge is connected"), mark; `PATCH /me/slack` `{ prefs }`; `DELETE /me/slack`. All `signed_in`, `SCOPE_OPEN` with the reason "a person's own row, keyed by who is asking".
- `src/components/SlackPanel.tsx` in My tasks: connected → "Connected to Slack · last message {time}" + four checkboxes + Disconnect; not connected → URL field, "Connect and send a test", a link to Slack's incoming-webhooks page.

### Task 4: The morning job and admin

- `Slack\Morning::schedule( string $hhmm )` (option `bwx_forge_slack_morning`, default `08:00`, WordPress timezone; `wp_schedule_event` daily, rescheduled on save; cleared on deactivation), `Morning::run()` → for each connected person with `morning` on: items where they hold a seat, not archived/terminal, `planned_due <= today`, grouped due today / overdue → one message (or "Nothing due today"); claim with occurrence = today's date as an int (`Ymd`).
- Connections admin page gains a "Slack" panel: the time field, "Send the morning message now", and the connected people with Disconnect buttons. `SyncScreen` gains "Slack messages that failed" (person, kind, detail, when).
- Route `POST /slack/morning` (`manage`) runs it now, for tests.
